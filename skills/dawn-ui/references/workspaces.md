# 存量项目与工作区

本文为 dawn-ui 独立补充。先识别变更类型，避免所有请求都变成重新设计。

## 存量项目的三条路径

| 请求 | 可以改变 | 应保留 | 先看什么 |
| --- | --- | --- | --- |
| 优化 UI、视觉改版 | 层级、布局、偶然形成的颜色/间距默认值 | 用户锁定品牌、产品事实、有效交互 | 代表页截图、设计变量、共享组件、同类页面 |
| 修复流程 | 入口、步骤顺序、反馈、恢复与必要布局 | 已有视觉语言和不相关流程 | 卡住的真实操作链、异常状态、返回路径 |
| 增加功能 | 新对象、新操作与其必要状态 | 现有导航逻辑、组件、词汇、权限模型 | 功能放在哪个任务附近，复用什么，新增后原任务还能否完成 |

基线记下受影响页面、视口与状态；从共用 token 或组件修问题，再验证代表性使用处。只改页面时不要顺手重命名目录、换框架或重建组件库。现有规范互相矛盾时，先用多数稳定做法；品牌级变更不能藏在局部精修里。

## 按工作方式选骨架

先写“用户主要在处理什么对象，用什么动作完成工作”。再选布局，不默认四张指标卡加几张图表。

| 核心任务 | 合适骨架 | 首屏重点 |
| --- | --- | --- |
| 批量查找、比较、审批 | 表格或队列＋筛选＋按需详情 | 对象身份、异常、下一步动作 |
| 阅读、检索资料 | 目录/检索＋正文，辅助信息按需展开 | 文本起点、当前位置、阅读宽度 |
| 连续编辑 | 主编辑区＋少量工具＋按需属性面板 | 当前对象、保存状态、撤销入口 |
| 调度与监控 | 时间线、地图或流程视图＋事件队列 | 变化、异常位置、处理入口 |
| 决策分析 | 一个结论/问题＋关键图表＋明细下钻 | 时间范围、口径、比较对象与行动 |
| 空间或多对象创作 | 画布＋对象导航＋上下文工具 | 选择范围、缩放、撤销与出口 |

详情用于解释前因后果与下一步，不能只是把表格每个字段再排一遍。频繁比较才并排显示；不常用日志、元数据和高级筛选收进按需区域。密度由任务决定，删除无用面板之后应使对象更清楚，不能只变空。

## 数据与操作的关系

- 时间范围、时区、刷新时间和指标口径靠近图表，颜色语义在各页一致；变化同时写基准、方向与数值，不用绿色暗示所有上涨都好。
- 图表先问用户要看趋势、分布、构成还是比较。精确读取保留数字或明细入口，颜色和 hover tooltip 不是唯一信息源。
- 批量操作显示选了多少、是否跨页、作用于当前筛选还是手动选择；刷新、筛选与分页后选择策略明确。破坏性操作可追溯到实际对象。
- 选中、焦点、悬停和状态色是四种含义，不能用同一个彩色胶囊表示所有东西。普通状态弱化，异常与主动作才突出。
- 返回列表保留筛选、页码和滚动；切换对象不丢草稿；保存状态和服务真实结果对应。

## 验收

对同一批对象完成一次真实任务，记录动作数、来回跳转和信息缺口；只在可比的实际操作后报告效率提升。检查长名称、缺失字段、大数值、多选、空结果与无权限。有共享样式修改时，至少复查一个未直接编辑但受影响的代表页。
