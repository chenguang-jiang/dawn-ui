# jcg-ui

先用一句设计北极星说明这个产品要让人看到什么、完成什么，再让构图、字体、色彩、素材和交互围绕它展开。让用户记住一两处，其余支持任务。界面的表现和任务是否走通分别验收。

本 Skill 以 Oil UI 的 MIT 开源内容为基础，另有独立编写的体验、工作区、组件和特效实践；不包含 Oil UI Pro 的非公开文件，不宣称与它等同，详见 [能力来源与限制](references/capabilities.md)。无需版本联网检查、自动覆盖安装或推广提示。只读当前任务需要的参考，产物放任务目录，不能写进 Skill 安装目录。

## 范围与推进方式

先明确用户、主任务、真实内容、设备和交付形式；只检查相关页面。用户锁定的品牌、结构、交互与参考优先。回复使用用户语言，界面使用产品受众语言。不要把“借鉴”“改版”“精准还原”相互替换。

缺失信息会改变核心方向且无法推断时才提问；其余作合理假设并推进。用户已授权直接完成、自行决定或无人值守时，自己选择并记录理由，不为内部流程增加审批。只要评审就保持只读；只要设计稿不默认改业务代码。

| 范围 | 路径 |
| --- | --- |
| 已明确改法的小改动 | 直接改；文案和数量按内容核对，颜色和间距看受影响区域。不做方向卡、全面审计或多轮评审 |
| 新页面、品牌探索 | 读 [设计方向](references/design-direction.md)；方向模糊时先给简短候选和推荐，用户要看比较或任务确实需要时再做首屏小样。用户已选方向或只要一个方向时直接深化 |
| 多风格实际比较 | 按 [风格对比页](references/style-explorer.md) 做代表性首屏，共享内容，不共享换色模板；不制作多套完整产品 |
| 存量项目优化、流程修复或新功能 | 读 [存量项目与工作区](references/workspaces.md)，先区分改什么，再留基线并从变量和共享组件源头修改 |
| 单个组件精修、卡片或空间展开 | 读 [组件与空间交互](references/components.md)，只扩大这个组件的完成度，不扩张产品范围 |
| 截图还原 | 读 [布局与视口](references/layout-and-viewport.md)，锁定参考逻辑视口，用截图对比，不探索新风格 |
| UI/UX 评审 | 读 [评审派发](references/visual-review.md) 和 [体验验收](references/quality.md)，按证据诊断；不要求重设计时尊重既有规范 |

## 1. 建立方向

从品类、受众、品牌和内容推导风格。参考先看真实画面，不凭产品名字或记忆推断；拿不到就说明来源局限。按 [设计方向](references/design-direction.md) 写出可观察的字体、色彩、主视觉与结构关系；说服型页面需要时读 [首屏骨架](references/direction-persuasion.md)。

- 内容页、工具和后台以真实内容与当前任务作为首屏；说服型页面才组织品牌开场。
- 多方向的结构、字体、色彩和主视觉要真正不同；用户锁定品牌时在结构和内容组织上比较，不为差异破坏品牌。
- 小样只做能判断方向的代表性画面，不先接全套交互。每张截图实际看过并修掉裁切、重叠后再交。
- 已授权自行决定时，按任务适配、内容承载、辨识度和实现成本选定。除非用户要求多个候选，否则不强制制作三套页面。
- 留一份简短设计说明：主任务与动作、方向及依据、关键状态、设备约束、记忆点和验收重点。已有说明直接更新。

## 2. 把结构与体验一起设计

按当前问题加载参考，不全量加载：

| 问题 | 参考 |
| --- | --- |
| 视觉层级、字体、色彩、空间、图标、减法 | [视觉语言](references/visual-language.md) |
| 素材选择、生成提示词、图文融合、3D 与视频 | [素材](references/media.md) |
| 按钮、表单、搜索、异步、权限、错误和弹层 | [交互与状态](references/interaction.md) |
| 桌面与手机的布局重排、放大、长文案 | [布局与视口](references/layout-and-viewport.md) 与 [交互与状态](references/interaction.md) |
| 后台、队列、表格、编辑器、数据看板 | [存量项目与工作区](references/workspaces.md) |
| 单组件、卡片选型、原位展开、抽屉 | [组件与空间交互](references/components.md) |
| 反馈、切换、出场、过渡与减少动态效果 | [动效](references/motion.md) |
| 品牌页的滚动叙事 | [滚动叙事](references/scroll-narrative.md)，由内容需要决定，不强加长滚动舞台 |
| 流光、点阵、渐变、SVG/Canvas/着色器 | [视觉特效](references/effects.md) |
| 小游戏、计时养成与强手感操控 | [游玩](references/play.md) |

先写主流程和会改变设计的状态，再完成默认画面。主操作、切换与出场有需要时采用同一套动作语法；高频任务、减少动态效果和静态需求优先。关键素材先选定或制作，再围绕主体、留白和裁切排版。没有素材表达需求就不加图。

沿用项目有效的变量、组件和技术栈。不为一页另造设计系统，不将无关重构混入设计任务。任务要求可运行界面时，关键操作要有可观察结果；演示动作和未接入部分在交付说明里说清，不能伪装真实提交或业务成功。

## 3. 制作与取证

先完成代表页或关键操作链，通过后再延展。小改动只检查受影响区域。模拟内容应像真实产品，但不虚构客户评价、业务指标或真实证据；生成素材与模拟数据写入交付说明。产品本身的本地保存、隐私和离线限制需要告知时照常写在界面里。

浏览、交互和截图优先遵守项目与宿主的工具规范；可选内置命令见 [工具](references/tools.md)。可用时用 `shoot.mjs` 批量截图、录屏、比对和生成报告；它的静态提示只是线索，不能代替看图、无障碍或业务验证。

- 证据标明页面、视口、状态与版本；长页看整体节奏和关键局部。
- 看真实阅读尺寸、中文断行、窄屏和关键区域的 200% 浏览器缩放。工具的 `--zoom 2` 是像素密度，不代替浏览器放大后的布局检查。
- 动效看正常速度录屏，连续操作和逆向操作；静态截图只能证明静态状态。
- 只重新取修改影响的证据；同一批改动集中检查，不因生成文件成功就宣称验证通过。

## 4. 评审、修正与停止

新页面、整体改版或主要任务变化，初版稳定后按 [评审派发](references/visual-review.md) 评审。方向小样先用于选择，不默认对每个小样重复评审；小改动由主 Agent 自检。能隔离上下文、能看图且宿主允许委派时才用独立评审者，否则按 [评审手册](references/reviewer-manual.md) 自检并写明“未独立评审”。

先改阻断、数据丢失、误导反馈和可读性，再处理视觉与手感。评审意见不能推翻用户锁定的约束；“保留”项写入设计说明，避免精修抹掉特色。规则见 [体验验收](references/quality.md)。

- 普通页面一轮评审修正后复查。用户明确要求精品打磨、或修正后仍有重要差距时，可在同一方向内再评，默认最多三轮；预算更低时按预算。
- 新设计可以用 9/10 作为品质目标，但每个分数必须附观察依据；没有真实画面不给分，不通过换模型评分或增加装饰追分。存量规范对齐不打分。
- 连续两轮没有可见收益、偏好互相冲突或方向漂移时停止美学迭代，说明剩余差距。未完成的必需功能继续处理，确有阻塞时如实列出。

## 5. 验证与交付

按 [体验验收](references/quality.md) 选择与改动相关的检查：主要流程从入口走到结果；有保存时刷新读回并验证失败后输入保留；有余额、次数和权限时检查相应边界；表单和弹层检查键盘、焦点及关闭返回。仅有视觉概念时不声称完成运行验证。

使用项目要求的门禁与相关验证脚本。改交互跑对应行为检查，改共享组件检查代表性使用处；生产构建或更广的测试按项目要求与风险决定，不因 Skill 全局禁跑，也不为纯文字调整建立长期测试系统。失败会影响交付时修复授权范围内的问题；外部依赖或环境阻塞说明影响，不擅改认证和部署配置。

最后做减法：移除重复文案、分隔和无关装饰，同时保留对象、状态、判断依据和主动作。交付简述方向、关键变化、验证结果和剩余项；有截图、录屏、评审记录时给出实际位置。不为每个小改动输出整套报告。

## 能力边界

没有看图能力就写明“未验证实际视觉”；没有可运行环境就不声称交互通过。工具不足时交付可用的部分与具体缺口，不捏造分数、帧率或性能改善。不自动接入付费服务、索取密钥或安装另一款 Skill；外部服务和素材使用遵守当前任务授权及条目许可。
