# 视觉特效的选择与实现

本文为 jcg-ui 独立补充。先写特效表达什么：数据流向、工作状态、空间层级还是品牌气氛。不能回答时先不加。以下是实现路径，不是固定的品牌皮肤。

## 按视觉任务选技术

| 需要 | 优先技术 | 关键约束 |
| --- | --- | --- |
| 元素上的柔和光斑或渐变 | CSS 背景、伪元素与 transform | 不把文字一起模糊，不持续重绘整屏 |
| 沿已知连线移动的流光 | SVG path＋dashoffset/遮罩 | 路径必须有实际关系，端点与对象对齐，保留静态路径 |
| 点阵构成图片或密集可动场 | 少量点用 SVG/CSS，大量粒子用 Canvas | 不为每个点建状态组件，限制点数与像素密度 |
| 连续形变与复杂材质场 | 已有 WebGL/着色器能力 | 检测上下文失败，提供同构静态图，释放 GPU 资源 |
| 真实物件转动、拆解和材质变化 | 实时 3D | 按素材参考里的光照、贴图、接触阴影要求检查 |

## 三个可落地的起点

**沿线流光**：把关系线定义为一条 SVG path，普通细线作为底层，亮段使用同一路径；用 `stroke-dasharray` 控制亮段长度，动画 `stroke-dashoffset` 表示方向。多条线共享时间但保留语义方向，不能随机流动。SVG 装饰层 `pointer-events: none`，业务节点仍是正常 HTML 控件；视口变化后按实际锚点重算路径。

**点阵与粒子**：先把图形采样到稳定网格，每个点存基准位置与当前位移；指针力只作用于附近范围，以阻尼回归基准位置。指针离开、页面隐藏或离屏时停止额外更新。触摸端使用静态或低密度版本，不抢走滚动。实际显示尺寸决定点间距，先做小面积验证再扩大。

**流动渐变**：先用两三层大色域和一个安静底色构成色场，再对色场图层做缓慢位移或旋转；文字在独立的稳定层。需要精细连续形变时才上着色器，给低性能设备固定色场。动画不传达数值，也不能替代真正的处理中状态。

## 预算与回退

先在目标设备或代表设备记录实际表现，再决定是否保留；不以“使用 GPU”声称流畅。优先复用已有依赖，单个光斑不新增整个动画框架。

持续动画限制在主视觉区域，离屏/后台停止，卸载时清理 observer、监听、requestAnimationFrame、纹理和材质。像素比按清晰度与成本设上限，窄屏降低复杂度。避免高频大面积模糊与阴影；只动画确实需要变化的属性。

减少动态效果时显示有意义的静态终态；内容从第一帧可读，特效加载失败不遮住主操作。禁止闪烁和频繁明暗跳变。用有语义的 DOM 提供文字与操作，装饰画布不进入读屏顺序。

## 验收

看静态构图、文字对比、实际动效录屏；测试窄屏、指针离开、快速切换、减少动态效果和 WebGL 不可用。记录已测设备与回退，不用桌面截图证明手机流畅。若只有静态稿，标明特效尚未验证。
